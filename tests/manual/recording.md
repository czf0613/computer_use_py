# 实际录制验收（必须先由用户准备并授权）

不要在自动化测试或 CI 运行这里的命令。测试会录制所选显示器和电脑播放的系统声音，
保存到用户指定的本地路径。不会采集麦克风，也不会自动授予系统权限。

用户先准备：

1. 选定要录制的显示器，清除其上不希望入镜的内容。
2. 准备一段带声音、可清晰判断音画同步的本地测试视频，或自建的闪烁画面/提示音。
3. 指定一个不存在的输出 MP4 路径，检查父目录存在、可写且有足够空间。
4. 为实际启动 Python 的应用准备屏幕录制权限；完成后明确允许开始测试。

在授权后获取显示器 ID：

```sh
uv run python -c 'from scapkit_computer_use import list_displays; print(list_displays())'
```

把下例的 `DISPLAY_ID` 和输出路径替换成用户选定的值后运行：

```sh
uv run python tests/manual/verify_recording.py --display-id DISPLAY_ID --output /absolute/path/recording.mp4 --duration 15 --fps 30
```

对比质量和体积时增加 `--video-quality 0.5`，保持相同场景、显示器、时长和帧率。
默认质量为 `0.75`；编码器自行分配码率。省略该参数即使用 `0.75`。

分别验收：

- 整段保持桌面静止且无系统播放声音：视频时长完整，可正常显示静止画面和静音。
- 开头静止、中间播放准备好的带声音视频、结尾再次静止：首尾时长准确、音画同步，
  画面只来自选定屏幕，其他应用播放的系统声音按预期录入。
- 至少连续播放 20 秒，比较开头和后半段的运动流畅度；不能只凭容器标注 30 fps、
  总帧数正确或解码成功判定采集流畅，需检查重复画面和实际画面更新频率。
- 改为用户选择的另一个帧率，核对输出帧率、分辨率及停止后的文件可用性。
- 在 QuickTime 中从头播放、拖动到中间和末尾，检查色彩、文字、声音及末帧。
- 如需确认麦克风隔离，在没有软件监听/回放麦克风的情况下讲话：成片不得包含该声音。
  若其他程序把麦克风回放到系统输出，该回放属于系统声音，会被录入。

脚本输出字节数、时长和每分钟 MiB，用相同场景比较文件大小。完成 H.264 的真实
录制评估后再决定是否新增 HEVC；合成小尺寸测试文件不用于估算真实桌面的压缩率。
